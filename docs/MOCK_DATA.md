# Mock 数据说明

本项目是课程实验 Demo，没有连接真实后端、真实支付、真实手机号授权或生产接口。所有业务数据均由前端 mock 数据提供，主要集中在 `utils/mock.js`。

## Mock 数据入口

所有 API 调用统一经过：

```text
utils/request.js
```

当前项目没有配置真实 `BASE_URL`，因此请求会进入：

```text
utils/mock.js
```

这种方式可以保留接近真实项目的 API 调用形式，同时保证课程演示不依赖服务器环境。

## 商家数据

商家数据包含：

- 商家 id
- 商家名称
- 评分
- 月售
- 起送价
- 配送费
- 距离
- 地址
- 电话
- 营业时间
- 经纬度
- 公告
- 标签
- 本地 SVG 图片

用于首页、商家列表、点餐页商家信息和地图页。

## 菜品数据

菜品数据包含：

- 菜品 id
- 所属商家 id
- 分类 id
- 菜品名称
- 描述
- 价格
- 销量
- 库存
- 本地 SVG 图片

用于点餐页、菜品详情、购物车和订单确认页。

## 搜索数据

搜索 mock 包含热门关键词和搜索结果。搜索逻辑会根据商家名称、标签、地址、菜品名称和菜品描述进行简单匹配。

用于：

- 热门搜索
- 最近搜索
- 搜索结果列表

## 登录数据

登录流程会优先尝试调用 `uni.login`。如果无法获得真实 code，则使用：

```text
mock_code
```

mock 登录返回：

- uid
- token
- openid
- nickname
- avatar
- gender
- cellphone

这些数据会保存到 Vuex 和 `uni storage`，用于个人中心展示和登录拦截。

## 验证码数据

手机号绑定使用 mock 验证码：

```text
123456
```

项目没有调用微信真实手机号授权，也没有发送真实短信。

## 订单和支付数据

提交订单时，项目会根据购物车数据生成 mock 订单。订单状态直接设置为：

```text
已付款
```

支付流程为模拟支付成功，不连接微信支付。真实项目中，订单金额、支付签名、支付结果校验都应由后端和微信支付能力完成。

## 地图和退款数据

地图页使用商家 mock 经纬度展示模拟地图，不依赖真实地图权限。

退款申请为前端组件模拟提交，不连接真实售后接口。

## Mock 设计目的

- 保证课程作业能运行。
- 保证没有 AppID、商户号、后端接口时也能演示。
- 保留真实项目常见的 API 分层写法。
- 方便截图和写实验报告。
